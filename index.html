연산 엔진·기술 차별성 4

엔진이 뭔데?

수치해석 엔진은 과학 현상을 설명하는 방정식을 풀어 실험 결과를 계산하는 소프트웨어입니다. 예를 들어 상미분방정식 ODE Solver를 통해 롤러코스터의 속도와 위치가 시간에 따라 어떻게 달라지는지 계산할 수 있습니다.

기존 엔진과 자체 엔진은 무슨 차이인가요? 기존 엔진을 쓰는 게 더 좋지 않나요?

범용 엔진을 활용하는 것도 좋은 방법입니다.

다만 범용 엔진은 다양한 산업과 개발 환경에서 사용할 수 있도록 상당히 많은 기능과 설정을 제공하고 있습니다.

저희는 MATLAB을 국산화한 CEMTOOL을 통해 수학·공학적 계산 기술을 확보해 왔으며, 이를 바탕으로 교육 콘텐츠에 필요한 기능을 중심으로 자체 엔진을 구성했습니다.

예를 들어 범용 엔진에서는 개발자가 다양한 물리 파라미터를 직접 설정하고 조합해야 한다면, 저희는 교육 콘텐츠에서 자주 사용하는 변수와 기능을 중심으로 미리 구성해 보다 간편하게 활용할 수 있도록 한 것입니다.

또한 불필요한 기능을 최소화하고 교육 콘텐츠에 필요한 연산과 기능 중심으로 구성할 수 있기 때문에 실행 용량과 성능 측면에서도 최적화할 여지가 있습니다.

결국 범용 엔진의 모든 기능을 사용하는 것보다, 저희가 실제로 필요한 기능을 교육 목적에 맞게 최적화하는 것이 이번 사업에는 더 적합하다고 판단했습니다.

어떤 특허를 보유하고 있나요?

클라우드 환경에서 수식과 행렬을 계산하고, 그 결과를 시각화하는 기술에 관한 특허입니다.

화면조작, 3D엔진, 연산으로 나눠 개발한다 하였는데 연산부분은 어떻게 개발한다는 건지?

화면을 구성하는 객체들 중 물리연산이 필요한 객체의 운동에 대해서만 미분방정식을 푸는 형태로 적용할 계획이다.
좀 더 구체적으로 이야기하면 상미분방정식, ODESolver와 유사한 함수를 주로 사용하는데,
일반 물리엔진 라이브러리와 비교하면 일반 물리엔진에서 특정 기능 사용 시 복잡한 파라미터를 가진 함수를 사용하게 된다.
하지만 저희는 3천종 이상의 시뮬레이션을 개발하면서 검증된 교육 컨텐츠에 특화된 사용하기 쉽고 경량화된 함수를 사용한다는 강점이 있다.

기존 콘텐츠·플랫폼 연계 3

현재 기 63종의 시뮬레이션에 대한 문제가 운영사의 문제 아니냐?

저희가 올해 처음 지능형과학실ON 운영사로 선정되어서 들어가보니 시뮬레이션 관련된 심각한 문제들을 확인할 수 있었습니다.
여러가지 문제를 해결하기 위해 다방면으로 원인을 알아본 결과 소스코드가 아닌 실행파일 형태로 납품되어 코드 유지보수가 불가능한 상황이였고,
왜 그런지 알아보니 이전 업체에서 해당 건을 재하청주고 실행파일만 받은 상황임을 알게 되었습니다.
이와 관련하여 67페이지 부록을 보시면 해당 상황에 대한 공식 결과보고서의 내용을 확인하실 수 있습니다. 이와 같은 여러가지 문제들을 재단과 지속적으로 공유하였고, 해당 문제점들이 이번 제안요청서에 과업으로 포함된 상태입니다.
문제 원인으로 돌아와서
해당 프로젝트는 3월에 끝나지만, 플랫폼 사업은 2월에 종료됩니다. 만약에 플랫폼 사업과 본 사업의 사업자가 다른 상황일 경우.
3월에 시뮬레이션 탑재 시 수업과 시뮬레이션을 연결하는 부분에서 문제가 발생한다면 올해와 똑같은 실수를 반복하는 것입니다. 저희는 2월에 34종 모든 콘텐츠에 대한 연동 테스트를 마무리하여 문제 발생 원인을 최소화 하겠습니다.

콘텐츠 메타데이터에는 어떤 항목이 포함되나요?

콘텐츠 검색·분류를 위한 메타데이터 항목입니다. xAPI는 학생의 학습 활동을 기록하는 규격이며, 콘텐츠 식별자를 통해 연결합니다.

성취기준 코드(2022년 개정), 학교급, 학년, 교과, 영역, 단원, 핵심 키워드, 콘텐츠유형(주,부), 차시 수, 운영 시간, 조작 변인 목록, AI기능 목록, 지원 기기 등.

기개발 콘텐츠와의 중복 방지를 위한 성취기준 코드 기반 검색 연계 방안 제시

- 기존 63종과 신규 34종에 성취기준 코드를 연결합니다. 하나의 콘텐츠가 여러 성취기준을 다루면 여러 코드를 등록합니다.
- 신규 콘텐츠 기획·검토 시 같은 코드의 기존 콘텐츠를 검색합니다. 기존 콘텐츠의 제목, 학습 목표, 실험 내용, 조작 변인을 함께 확인합니다.
- 비교 결과로 중복 여부와 차별점을 판단합니다. 학습 목표와 실험 활동까지 같다면 조정하고, 같은 성취기준이어도 탐구 방식이나 다루는 변인이 다르면 차별점을 기록합니다.
- 플랫폼에서도 해당 코드의 관련 콘텐츠를 조회하도록 연결합니다. 검색 항목과 데이터 형식은 플랫폼 운영사업자와 협의합니다.

실제 학생의 학습 상태는 여러 요소가 복합적으로 작용합니다. 정답은 맞혔지만 풀이 시간이 오래 걸릴 수도 있고, 정답률은 낮더라도 최근 학습 성과가 빠르게 향상되고 있을 수도 있습니다.

이처럼 서로 다른 학습 신호를 종합해 학생에게 가장 적합한 난이도 조절 전략을 찾기 위해 강화학습을 적용하겠습니다.

학생의 정답률, 풀이 시간, 오답 유형, 힌트 사용량 등을 상태 정보로 활용하고, 문제 난이도를 조절하는 행동을 학습하도록 설계하겠습니다.

제안요청서에 나와있는 AI프록시 서버에 관해 말씀드리면 현재 재단은 재단에서 운영중인 모든 플랫폼에 연결되어 있는 외부 AI 서비스를 bizRouter라는 국산 LLM 서비스로 통합하고 있습니다. bizRouter의 특징 중 하나는 개인정보 마스킹 기능이 있다는 것입니다.
그리고 현재 플랫폼(지능형과학실ON)에는 이미 챗봇 및 보고서 튜터링 기능을 위한 AI서버가 구축되어 있습니다. 제안요청서에서 말하는 AI프록시 서버가 바로 이것입니다. 저희는 이미 AI 프록시 서버에 대해 다 알고 있고, 보고서 튜터링과 챗봇을 연결한 것처럼 시뮬레이션을 연결해주기만 하면 됩니다.
